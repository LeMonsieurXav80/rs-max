## File API (Facebook, Instagram, YouTube, Bluesky)

Réponses aux commentaires reçus par les API officielles ; la prélecture ne retient que les comptes `api_ready` avec persona et action `reply` activée.

Sur chacun des cinq passages, traiter jusqu'à `batch_max` réponses par compte, au plus 60 en deux lots de 30. Au premier lot, charger `reply-contexts --account ID --limit N` avec N égal au plus petit de 30 et `batch_max`. Le contexte donne un persona, les publications et les échanges. Écarter une cible si le contexte ou un média nécessaire manque. Un commentaire direct peut recevoir une réponse pertinente ; une relance doit contenir une question. Rédiger ensemble toutes les réponses retenues, puis les remettre **en un seul appel** : `replies --json '[{"id":ITEM,"context":"UUID","text":"RÉPONSE"}]' --commit`. RS-Max les envoie selon la cadence du compte. Enregistrer les `review` avant le lot suivant. Quand la prélecture contient d'autres IDs et qu'il reste du budget, charger les nouveaux contextes (30 au plus). N'utiliser chaque ID qu'une fois par passage et compter les réponses mises en file dans `batch_max`. Passer ensuite au compte suivant. `refused` dans le résultat ne concerne que sa cible ; `check_required` : déjà demandée, ne rien renvoyer.

Tous les comptes éligibles dans le même passage. Au passage suivant, `reply-status ITEM` seulement pour une réponse signalée incertaine.

Facebook programme le like lui-même après preuve de la réponse si `auto_like` est vrai. Remettre tout le lot sans attendre les likes. Aucun like Instagram, YouTube ni Bluesky par ce parcours ; Bluesky : 300 caractères au plus. Facebook : `inbox-like ITEM --commit` pour un like seul, avec relecture API et mémoire anti-renvoi. Un résultat incertain : vérifier l'état enregistré avant de poursuivre sur ce compte, jamais réessayer.
