## File TikTok (navigateur Companion)

**Inbox.** Les réponses aux commentaires reçus et leur like automatique sont autorisées, avec le persona actif. Cinq passages par jour : `reply-contexts --account ID --limit N` une seule fois, N = `batch_max` (30 au plus), puis rédiger ensemble et remettre en un appel `replies --json '[{"id":ITEM,"context":"UUID","text":"RÉPONSE"}]' --commit` : le téléphone envoie tout en un passage, chaque réponse avec son like et sa preuve après rechargement, sans `reply-status`. Refus 422 « contexte individuel » (Companion) : ouvrir les IDs les plus anciens par groupes de quatre avec `reply-contexts --ids ID1 ID2 ID3 ID4` (terminal `timeout:480`), puis remettre les réponses par `replies --commit`. Jusqu'à 20 réponses par compte, dans `batch_max`. « File du téléphone pleine » (409) : arrêter les réponses pour ce cycle. Au cycle suivant, `reply-status ITEM` sans `--wait` pour les réponses du cycle précédent. Réserver deux gestes par réponse. Réponse de 150 unités UTF-16 au plus, légende lue obligatoire. `addressing` : `interpelle` pour un commentaire sous la vidéo ou une réponse au compte, `participant` quand la personne répond à quelqu'un d'autre (`repond_a`) : alors jamais de remerciement. Le contexte contient la légende, les échanges connus et `vault` si des sources sont rattachées. Un quota de prospection nul ne bloque pas ces réponses ; le quota `comment.like` concerne la prospection dans le flux.

**Incertitude.** Après un délai ou un résultat incertain, RS-Max relit seul (5 puis 30 minutes après) : ne pas appeler `verify-reply`, ne jamais renvoyer, passer au commentaire suivant dès que la tâche est terminale. Une réponse ou un like de l'inbox incertain ne suspend jamais le compte, même s'il reste dans les journaux ou au cycle précédent ; `status ID` ne vaut que pour un reçu de découverte. Aucune relecture quand TikTok a retenu la réponse (`comment_status` 2). HTTP 200 ou une visibilité au seul auteur ne prouvent pas une publication. Service natif indisponible : le signaler, sans repli simulé.

**Découverte (`priority_tiktok`).** Après l'inbox, ou immédiatement sans candidat inbox : `discover --account ID --target COMPTE_CIBLE --limit 5` si une cible pertinente est configurée, sinon `scan --account ID --limit 5`. Au plus un commentaire ou un like pertinent par passage, selon `write_actions`. Pour commenter : `comments --account ID --url URL`, puis `comment-context --account ID --snapshot UUID` ; utiliser le persona et tous les commentaires accessibles quand `accessible_complete` ou `complete` est vrai, enregistrer le nombre lu sans prétendre avoir lu le reste ; `complete:false` interdit la rédaction. Envoyer `comment --account ID --snapshot UUID --context UUID --text "COMMENTAIRE" --commit`. Like de vidéo : `like` avec le snapshot du flux ; like de commentaire : `like-comment` avec le snapshot de discussion et `--comment-key`. `status ID` si un reçu est encore en cours. Respecter le statut confirmé ou incertain retourné, sans renvoi. Le cycle ne publie aucune vidéo ni photo.
